# 10 — Гейты и доказательства

Канонический дом целостности гейтов, канона доказательств и формата отчёта владельцу. Self-audit A–G —
[04-audits-triada.md](./04-audits-triada.md); housekeeping-гейты — [08-housekeeping-and-pre-flight.md](./08-housekeeping-and-pre-flight.md);
формальные правила — [RULES.md](../.claude/RULES.md) (R9).

## Зачем

Агент, закрывающий волну или эпик, отчитывается словами — «тесты зелёные», «ссылки не битые». Слова
агента — заявление (claim), не факт. Гейт превращает заявление в факт: берёт команду, её вывод и
exit-код и даёт один воспроизводимый вердикт, который любой другой участник может перегнать и получить
тот же ответ. Но гейт, технически существующий, а красным его никто никогда не видел, — декорация: он мог
быть сломан с рождения (не тот импорт, не тот файл сравнения, тихий пропуск нечитаемых файлов) и годами
показывать «чисто» независимо от реального дефекта. Отличить «работает» от «всегда отвечает одно и то же»
можно одним способом — показать ему заведомо испорченный вход и проверить, что вердикт меняется.

## 1. Четыре правила целостности гейта

1. **Позитивный контроль обязателен для каждого гейта.** Гейт, умеющий сказать «чисто», в том же прогоне
   доказывает, что умеет сказать «грязно» — на фикстуре, отличающейся от чистой ровно дефектом, который
   гейт ловит. Лучшая грязная фикстура — артефакт реального прошлого инцидента.
2. **Отсутствие ошибки — никогда не PASS.** Пустой вывод — провал, не зелёный по умолчанию. Живость —
   отдельный сигнал от бизнес-вердикта. Exit-код читается первым, до текста; обёртка процесса на части
   платформ возвращает свой exit-код независимо от обёрнутой команды (см. §4).
3. **Вердикт «flake» — только при n ≥ 5 с явной долей.** Один красный прогон — красный прогон; «шум» по
   единственному наблюдению не квалификация.
4. **Ни одного утверждения без инструмента.** Число получено скриптом (парсер лога, обход реестра) и
   указывает на файл-доказательство рядом, не вписывается из памяти.

**Честный минус.** Доказанный набор гейтов не ловит: новый класс дефекта без ещё не написанного контроля;
фабрикацию нарратива способом без своего гейта отчётного слоя (§3); человеческое суждение (замысел,
приоритет); слепое пятно автора, повторённое в его же тесте (§6). Гейты сужают пространство недоверия, не
закрывают целиком — приёмка человеком ([11](./11-acceptance-and-final.md)) остаётся отдельным слоем.

## 2. Механизм: реестр → контроль → мета-гейт

**Реестр** — один машиночитаемый список, не документ: id, `invocation` (команда), `verdict` (regex
«чисто»/«грязно» + exit-коды; часть гейтов держит вердикт в печатаемой строке/JSON, а не в exit-коде),
`control` (скрипт-контроль или `null`), `reason` (обязателен при `control: null`), `gatesWhat` (обязателен
при рутинном close или только при отгрузочных событиях), `timeoutMs` (для легитимно долгих живых
проверок). Секция `non_gates` называет скрипты, сознательно не являющиеся гейтами (отчётные утилиты,
мутирующие обслуживающие действия, признанный техдолг) — тоже с причиной. Скрипт либо гейт с контролем,
либо гейт с явной причиной отсутствия контроля, либо осознанно вне системы — тихо забытых не бывает.

**Общий контракт контроля** (один shared-модуль, не переизобретается в каждом): запуск без shell с
таймаутом, разделяющий обычный провал и «интерпретатор не найден» (`SETUP-ERROR` — не проверено, не
«ошиблось»); классификация одной «ноги» как `PASS`/`FAIL`/`TIMEOUT`/`SETUP-ERROR` (пустой вывод стартовавшего
процесса — `FAIL`); одна финальная строка `CONTROL <id> PASS|FAIL нога=exit:matched ...`, `PASS` только
если все ноги PASS.

**Мета-гейт** читает реестр, для каждой строки с `control` спавнит его и печатает одну строку
`GATE-INTEGRITY: fail=N missing=N misclassified=N timeouts=N` (exit 0 только при всех нулях), плюс «пол» —
минимальное число зарегистрированных гейтов, чтобы реестр не мог тихо съёжиться до пустоты и остаться
«зелёным». Он же — строка в собственном реестре: каждый боевой прогон проверяет и себя, но только против
тестовых фикстур, никогда против боевого файла.

**Набор гейтов события вычисляется, не поддерживается текстом**: флаг `--list close|ship|all` печатает id
по полю `gatesWhat` без запуска контролей — это и есть «набор close-цикла», а не отдельный список в
документации, который может разойтись с реестром. Мета-гейт запускается **последним** в close-бандле —
часть контролей отчётного слоя (§3) сканирует транскрипты, которые пишет сам бандл.

## 3. Каталог классов гейтов

| Класс | Что ловит | Как доказан «красный» |
|---|---|---|
| Ссылки и канон доков | битая ссылка, нерезолвящийся якорь-указатель «см. канон: путь#якорь», утверждение доки против устаревшего факта (протухший npm-скрипт/файл/маркер) | фикстура с висящей ссылкой/якорем/маркером; код-спаны и цитаты замаскированы |
| Кодировка и PII | replacement-символ, невалидные байты, BOM, двойное кодирование, личные пути в транскриптах | грязная фикстура на каждый класс дефекта |
| Дрейф реестров и окружения | несколько копий одного перечня разошлись; набор ключей окружения не совпал с таблицей значений | построчная сверка без импорта конфигов; фикстура с пропущенным ключом |
| Живость служебных процессов | сервис не отвечает или отвечает не тем набором команд | рукопожатие с фикстурой неотвечающего/устаревшего процесса |
| Скоуп прод-кода | diff-строка попала в прод вне разрешённой тестовой зоны; литеральный адрес/порт в тесте вместо конфига | фикстура-diff в запрещённой зоне; фикстура с литералом |
| Дисциплина удаления на шве | удалённая непустая строка без маркера причины | фикстура с удалением без маркера |
| Отчётный слой (форма/число/шапка/метки/разрывы) | BOM/пустой транскрипт без маркера завершения; число без пути к git-доказательству; шапка расходится со счётчиками тела; метка журнала позже коммита, добавившего запись; пауза между записями без маркера | грязная фикстура на каждый вариант; построены на реальных случаях фабрикации |
| Живая инфраструктура | защищённые/постоянные имена задеты чисткой временных объектов | несколько ног на живом стенде: чистка = ровно реестр, защищённые целы |
| Обёртка стороннего юнит-раннера | сторонний тестовый пакет красный/зелёный | тот же контракт «строка + exit-код» поверх внешнего раннера |

## 4. Канон доказательств

- Число гейта без транскрипта в ветке (UTF-8 без BOM, LF, на описываемой голове) не существует —
  «не измерено».
- Число в **шапке** — заявление; доказательство — вывод парсера над телом, воспроизведённый проверяющим.
  Прецедент: шапка «все N ПРОШЛИ» при провале в теле того же файла; «все карточки прошли с первого
  раунда», прячущее провальные раунды из истории прогонов.
- Числа выводит скрипт над журналом/индексом, не вписываются рукой; «замороженные» числа несут команду,
  которой получены — без деривации число выживает в отчётах как выдумка.
- Транскрипт несёт проверяемое дерево (путь и `git rev-parse HEAD`) — без привязки любое производное
  утверждение ложно по построению.
- Рецепт: `{ echo "# tested_head <hash>"; echo "# command: <cmd>"; timeout <s> <cmd> 2>&1; echo "EXIT=$?"; } > <file>`
  — UTF-8 без BOM, LF, последняя строка — истинный `EXIT=<n>`, захват через bash-редирект, никогда через
  оболочки, вставляющие UTF-16/BOM/CR.
- Гейт без запуска не имеет exit-кода: `N/A` в заметке с причиной, никогда транскрипт с рукописным `EXIT=0`.
- Закрывающий транскрипт валиден только для дерева, которое поздняя правка не тронула внутри измеряемой
  зоны — журналы хода работ включительно; метки времени берутся из git/системных часов, не вписываются
  рукой — рукописные дрейфуют к круглым/будущим значениям.
- Артефакты отчёта существуют в сданной ветке — доказано `git ls-files`/`git show HEAD:<path>`, не рабочей
  копией. Exit-код обёртки не всегда exit-код команды — рядом печатаются свои счётчики инструмента. Гейт
  «всё живо» называет охват — «ОК» без уточнения охвата сам дефект отчётного слоя.

## 5. Формат отчёта владельцу (канон)

Любой отчёт оркестратора владельцу (волна, close/STOP, приёмка, FINAL) — **один** огороженный markdown-блок,
копируемый одним кликом; симметрично — команда техлида оркестратору.

**Почему.** Владелец переносит отчёт копипастой в чат техлида. Вне блока таблицы разваливаются, вывод
`git log --graph` теряет форму, хэши рассинхронизируются — доказательная часть гибнет первой при переносе.

| Требование | Причина |
|---|---|
| Один блок на весь отчёт | несколько блоков — потерянные куски между ними |
| Внешняя ограда — ЧЕТЫРЕ обратных апострофа (бэктика), язык `md` | внутри живут тройные ограды команд; тройная внешняя рвётся на первой внутренней |
| Заявления — дословный вывод команды, не пересказ | прецедент: «SCAN CLEAN» заявлено в отчёте, где сообщалась битая кодировка |
| Ничего вне блока, кроме одной строки-подводки | подводка — не место для проверяемых заявлений |
| Числа — «N passed / M failed / K skipped» | прецедент: однобуквенная запись прочитана превратно |

Отчёт не в этой форме — не сдан, пересдаётся, а не оспаривается. Скелет (заполняемый шаблон —
[owner-report.md](../.claude/templates/owner-report.md)):

`````md
````md
## Отчёт: <волна|close|STOP|приёмка|FINAL> — <epic-id>

**Статус:** <ACCEPTED / NOT ACCEPTED / STOP / GO-ожидается>

### Сделано
- <пункт>

### Гейты
N passed / M failed / K skipped
```
<команда>
<хвост вывода>
EXIT=0
```

### Открытые вопросы владельцу
- <вопрос>
````
`````

## 6. VERIFIED vs DISPATCHED; тест обязан кусаться

Агент, раздавший работу под-исполнителям, не заявляет готовность до возврата каждой единицы; отчёт
разделяет `VERIFIED` (проверено лично) и `DISPATCHED` (запущено, возврат не подтверждён). Исполнитель без
доступа к файлам/командам не имеет в цикле ничего, что отличило бы правдоподобную догадку от верной —
давайте реальный доступ, не полагайтесь на самоотчёт. Приёмка теста не зависит от автора: тест обязан
**кусаться** — мутация защищаемой строки обязана окрасить его красным; переживший мутацию зелёный тест —
проваленный тест. После прерванного прогона сначала читают диск на предмет реального исхода шага, и
только потом решают, повторять ли его.

## 7. Антипаттерны и чек-лист «постройте у себя»

1. Гейт без контроля — «явно работает», пока сломанный импорт не держит его вечно зелёным.
2. Молчание = успех вместо провала.
3. Число без транскрипта — воспроизвести неоткуда.
4. Отчёт вне огороженного блока.
5. Flake по одному наблюдению без n ≥ 5.
6. Гейт над журналом до последней записи — проверено не то дерево, которое сдаётся.

Построение системы: один реестр, не документ; пустой вывод = провал; разделять «не стартовало» и «нашло
проблему»; контроль на каждый гейт; общий shared-модуль; мета-гейт, агрегирующий все контроли; набор
событий — фильтр по полю реестра; явный список «не гейт, и почему»; отдельная группа гейтов отчётного
слоя; периодическая живость служебных процессов отдельно от бизнес-логики.
