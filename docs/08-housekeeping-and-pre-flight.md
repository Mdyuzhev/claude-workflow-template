# 08 — Housekeeping and Pre-flight

Cleanup-эпики между фичами и pre-flight-чек перед каждым новым крупным эпиком — невидимая часть
процесса, критичная для долгого проекта.

## Зачем нужен housekeeping

Без регулярной чистки: в корне репозитория копятся ad-hoc логи и hotfix-скрипты; сборочные каталоги
и старые installer'ы занимают гигабайты; `.claude/fitch/` после десятков эпиков превращается в
свалку; `git worktree` от прошлых параллельных работ остаются висеть; `CLAUDE.md`-файлы по дереву
устаревают; закрытые эпики мешают видеть активные; **реестры merged-состояния отстают от факта
слияния** — это отдельный, повторяющийся класс проблемы (не разовая случайность), и housekeeping
обязан сверять его на каждом прогоне, а не только когда кто-то заметил расхождение.

## Housekeeping-эпики — структура

Отдельная именованная периодическая линия эпиков (не ad-hoc номера каждый раз) — pre-flight перед
следующим крупным эпиком.

### Типичный охват

1. **Disk cleanup** — устаревшие сборки, дублирующиеся большие бинарные артефакты, старые логи,
   заброшенные `git worktree`.
2. **Archive moves** — закрытые эпики в архивный каталог задач, старые fitch-пакеты в архив по
   диапазону, устаревшие статус-файлы.
3. **Сверка реестров с фактом слияния** — `CLAUDE.md`/`ROADMAP.md`/реестр fitch/`REFERENCE.md` несут
   merge-hash и тег для каждого закрытого эпика; расхождение — не редкий баг, а типовой класс,
   проверяемый на каждом housekeeping.
4. **Docs refresh** — корневой и per-module `CLAUDE.md`, `WORKFLOW.md`, `REFERENCE.md` с новыми
   уроками, дорожная карта с текущим состоянием.
5. **Docs-диета** — стартовый набор документов, которые агент читает на входе в сессию, целенаправленно
   измеряется в килобайтах и периодически урезается: перенос содержимого без потери смысла (move-only,
   с механизированной проверкой, что множество строк до и после переноса совпадает построчно), не
   удаление информации. Канон и метод — [docs/14](14-knowledge-and-context.md).
6. **Retention артефактов прогонов.** Логи и транскрипты накапливаются быстрее, чем успевают
   устаревать. Правило удержания: последние N прогонов + все красные прогоны в отдельном, более
   длинном окне + любой прогон, на который ссылается закоммиченный отчёт или baseline (такой прогон
   не удаляется никогда). Перед реальным удалением — dry-run превью кандидатов с датами, отдельно
   просмотренное до включения реального удаления явным флагом.
7. **Чистка веток** — только после доказательства тождества дерева со смёрженной точкой, не по факту
   «выглядит смёрженной».
8. **Memory refresh** — устаревшие записи памяти ассистента чистятся, актуальные добавляются.

### Периодичность и длительность

Между крупными эпиками, и отдельно — раз в несколько эпиков даже без специфичного триггера; перед
передачей репозитория новому участнику; после серии регрессий. Обычно один-два коммита без
изменений продуктового кода (что отдельно проверяется гейтом «нулевого прикосновения»), от часа до
нескольких часов при многокорзинном housekeeping.

## Чек-лист как машинный реестр

Человекочитаемый чек-лист «что проверить перед закрытием эпика» одновременно существует как
машинный реестр пунктов (идентификатор, заголовок, категория применимости, режим проверки), который
читает close-конвейер программно, а не человек глазами — устройство и вердикты конвейера
подробно в [mcp/03-close-conveyor.md](../mcp/03-close-conveyor.md); этот документ — источник
формулировок и общего порядка ритуала, конвейер — источник машинных id и категорий тех же пунктов.

## Pre-flight чек перед эпиком

Отдельная, более короткая активность (от получаса до пары часов) перед стартом конкретного крупного
эпика:

1. **Git clean state** — рабочее дерево чистое, нет неожиданных немёрженных веток или stash'ей.
2. **Свежий baseline по loose-ref'ам** — текущие числа гейтов и текущий HEAD берутся заново
   командой, а не по памяти о прошлой сессии.
3. **Живость MCP-инструментов** — гейт живости отвечает по каждому используемому серверу; если
   недавнее слияние поменяло контракт (новый ключ окружения, новая команда) — соответствующий сервер
   помечается «нужен рестарт», и до рестарта прогоны идут прямым вызовом того же обработчика.
4. **Стенд/моки подняты** — окружение для end-to-end проверок отвечает на smoke-запрос до первой
   строчки кода.
5. **Зависимости установлены в каждом рабочем дереве**, которое будет использоваться (включая
   вложенные подпроекты со своим файлом зависимостей) — их отсутствие всплывает только на первом
   прогоне гейта и стоит времени на ровном месте.
6. **Нужные инструменты — на `PATH` и той версии, что нужна.** Проверяется наличие и версия
   (`<tool> --version` против референсной), и только при отсутствии или несовпадении скачивается
   ровно нужный билд в постоянное место — не «на всякий случай», что копит мусор и даёт плавающие
   красные от версии, которая просто «похожа».
7. **Зависимые эпики уже слиты** — если эпик использует артефакт другого эпика, тот эпик должен быть
   в основной линии, а не в отдельной ветке.
8. **Изоляция файлов проверена** текстовым поиском по будущему плану волн (см. `06`).
9. **Для рефакторинг-эпиков** — замеры производительности сделаны ДО правок; без данных
   «оптимизация на глаз» не производится.
10. **Для UI-эпиков** — макет одобрен владельцем.
11. **Для средних/крупных эпиков** — self-audit пройден.

## Реальные кейсы (обобщённо)

**Кейс 1 — pre-flight housekeeping.** Обновлены `CLAUDE.md` зон, два созданы заново под новые модули;
корневой файл переписан как редирект + карта. Удалены hotfix-логи в корне, устаревший файл плана,
десятки старых логов прогонов (оставлены актуальные), пустой каталог задачи, десяток `git worktree`.
Один коммит cleanup + один docs sync, около двух часов.

**Кейс 2 — реструктуризация каталога fitch-пакетов.** Несколько десятков пре-проектных и закрытых
пакетов разнесены по архивным диапазонам, активные остались на верхнем уровне; десяток `git worktree`
удалён (один — под текущей сессией, не тронут). Около двух часов, после — каталог навигируем.

## Анти-паттерны

1. **Housekeeping откладывается «на потом».** Без чистки полгода — репозиторий неуправляем.
2. **Чистка «заодно» внутри фичевого эпика.** Cleanup — отдельный эпик, не inline-решение.
3. **Pre-flight пропущен для «уже отработанной» серии.** Экономия минут стоит потом часов диагностики.
4. **Замеры для рефакторинга не сделаны.** Без профиля до/после «оптимизация» — шум без эффекта.
5. **Docs refresh забыт.** Следующий агент планирует от неверного текущего состояния.
6. **Память ассистента не обновлена** после закрытия эпика — путаница в следующей сессии.
7. **`git worktree` накапливаются** без чистки — путаница, кто где работает.
8. **Retention без dry-run** — удаляется прогон, на который ссылается уже закоммиченный отчёт.
9. **Ветка удалена без доказательства тождества дерева** — «выглядит смёрженной» не доказательство.

## Чек-лист housekeeping-эпика

- [ ] Ветка отдельной периодической линии создана от чистого основного состояния.
- [ ] Disk cleanup сделан, освобождённое место зафиксировано.
- [ ] Archive moves сделаны, структура после — навигируема.
- [ ] Реестры merged-состояния сверены с фактом слияния (§ выше).
- [ ] Docs refresh сделан, ссылки проверены.
- [ ] Retention артефактов прогнан с dry-run превью перед реальным удалением.
- [ ] Docs-диета (если применимо) прошла move-only проверку без потери смысла.
- [ ] Memory refresh сделан.
- [ ] Код-регрессия отсутствует (счётчики компиляции/юнит-тестов/смоука «было/стало» равны).
- [ ] Один-два коммита, conventional-сообщение.
- [ ] Исполняемая форма — через close-конвейер (`mcp/03`), не ручная сверка чек-листа глазами.

## Чек-лист pre-flight перед эпиком

- [ ] Git state чистый; MCP-инструменты живы, NEEDS-RESTART (если есть) явно задекларирован.
- [ ] Свежий baseline зафиксирован по loose-ref'ам.
- [ ] Стенд/моки подняты, зависимости установлены в каждом рабочем дереве.
- [ ] Нужные инструменты на PATH нужной версии — ничего не скачано «на всякий случай».
- [ ] Зависимости-эпики слиты; изоляция файлов проверена.
- [ ] Замеры сделаны (если рефакторинг); макет одобрен (если UI); self-audit пройден (если крупный).
- [ ] Владелец дал OK на старт.
