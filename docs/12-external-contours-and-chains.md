# 12 — Внешние контуры исполнения и цепочки эпиков

Как передать многозвенный эпик модели, которая не является Claude, и держать её работу
проверяемой, а не только правдоподобной. Канон цикла в целом — [PIPELINE.md](../.claude/PIPELINE.md);
раунды приёмки — [11-acceptance-and-final.md](./11-acceptance-and-final.md).

## Зачем нужен внешний контур

Внешний контур — не-Claude модель внутри стороннего агентского CLI, разведённая на две роли
(оркестратор + кодер), которую
ведёт headless Оркестратор (CC) через мост-MCP. Причина — стоимость и параллельная мощность:
второй эпик идёт во внешнем контуре, пока Оркестратор своими субагентами ведёт первый.

Честная калибровка:

- **Нормальный профиль** — разведка, точечные инфраструктурные задачи с живыми контролями,
  ограниченные fix-задачи в связке «оркестратор+кодер»; режим «оркестратор» включается явным
  флагом и иногда требует подталкивания.
- **Марафон точности** (долгая связная продуктовая работа) внешняя модель тянет только под живой
  рамкой человека — дорого; по умолчанию марафоны остаются за Оркестратором + субагентами, пока
  hook возобновления (ниже) не доказан в поле, а не на разовой репетиции.
- **Текстовые политики** внешняя модель соблюдает только там, где они механизированы гейтом или
  даны живой командой — общий принцип границ доверия:
  [RULES.md R8](../.claude/RULES.md#r8-границы-доверия-инструкции-данные-секреты).
- **Доминирующая статья расходов** — обвязка, не модель: много сжатий → много ручных вставок
  команды продолжения; инжектированные родительские документы составляли основной объём чтения на
  одном длинном прогоне (отсюда рабочие файлы цепочки вне обычных доков, ниже).

## Роли

| Роль | Что делает |
|---|---|
| Владелец | поручение и решения; ответы на HALT/вопросы; приёмка — единственная плановая внешняя остановка |
| Оркестратор (CC) = **лид** | запускает/модерирует контур; пишет решения строками DEC; держит бюджет вмешательств; проверяет волны по диску; за ним — регресс-прогоны, деплой окружений, слияние/теги/push |
| Внешний оркестратор | роль CLI: карточки, журнал прогресса и решений; код не пишет |
| Внешний исполнитель карточек | одна карточка за раз; слияния/ребейз/хард-ресет/push/теги вне периметра |

Обе роли — одна внешняя модель, фиксированный уровень рассуждения, без человека в цикле — headless.

## Мост-MCP: run/status/wait/stop/stats

- **запуск** — один процесс на цель/сессию (повтор в занятый каталог отклоняется); spawn без
  shell; есть dry-run, ничего не создающий;
- **снимок** — фаза, живость, простой ДВУМЯ способами (рост лога и изменение дерева) —
  эффективный простой это меньшее: верхнеуровневый лог молчит, пока под-задача работает;
- **ожидание** — блокирующий опрос до первого нового события (завершение / сентинел / коммит /
  под-задача / застой — «ни роста лога, ни изменений дерева», один раз за эпизод);
- **остановка** — убивает всё дерево процессов, идемпотентна на завершённом;
- **сессии/статистика** — только метаданные через одноразовую копию хранилища: тайминги,
  скорость токенов, подозрение на «переполнение рассуждения» (лимит длины без текста/вызова).

Мост никогда не открывает файлы учётных данных внешнего CLI.

## Модель цепочки: звено, ветка, PR

- отдельная ветка на звено от вершины цепочки; PR звена — чекпойнт, **сам не сливается**;
- по завершении — один кумулятивный PR, заменяющий звеньевые; слияние только через него;
  новые цепочки часто сводят это к одной ветке/каталогу с внутренними волнами — принцип
  «звеньевой PR = чекпойнт» сохраняется;
- «автономно» = без вопросов между звеньями, не «один непрерывный прогон»: малые инкременты,
  состояние на диске после каждого коммита, упавшая сессия продолжается с того же места;
- незакрытое звено — честный deferred-пункт кумулятивного PR с причиной, не остановка; «не успели
  по времени/бюджету» не причина — только техническая, после двух неудачных попыток;
- `CHAIN-DONE` при незакрытом обязательном пункте леджера — провал, не завершение.

«Отчёт по звену — не остановка»: следующая единица стартует немедленно. Две внешние остановки —
приёмка владельцем и `HALT:`.

## Рабочие файлы цепочки

Chain-brief, `progress.md`, `decisions.md`, `cards/`, `evidence/`, `acceptance/` живут в отдельном
каталоге верхнего уровня, не под деревом внутренних процессных доков команды: чтение файла оттуда
у части внешних CLI триггерит подмешивание родительских документов в контекст (наблюдалось —
инжектированный корневой документ составил большую часть объёма чтений на одном прогоне). Тонкий
защитный файл (≤1 КБ) наверху такого каталога экранирует его от того же класса инъекции.

- **Chain-brief** — лид пишет один раз, вбирая бриф поезда
  ([13](./13-merge-trains-and-parallel-lines.md)): базовый коммит/ветка/каталоги; роли и правило
  «один инструмент управляет процессом одновременно»; границы лида; контракт карточек; чек-лист
  модерации из прошлых провалов; допустимые остановки; волны+гейты; «вне скоупа»; неприкосновенные
  инварианты; форма сдачи. Шаблон `kit/templates/chain-brief.md`.
- **`progress.md`** — дописываемый журнал; записи не переписываются; заголовок несёт UTC-метку
  (гейт разрывов краснеет на молчании без сентинела); Entry 0 — дословный результат уведомления о
  старте ДО первого коммита (без неё цепочка не начата); каждая запись — сделано / гейты /
  следующий шаг. Шаблон `kit/templates/progress.md`.
- **`decisions.md`** — журнал решений отдельно от нарратива, метка времени события, решения
  владельца близко к цитате; поздняя запись может отменить раннюю, ранняя остаётся видимой.
  Шаблон `kit/templates/decisions.md`.
- **`cards/`** — см. ниже; **`evidence/`** — стенограммы исполнителя по волнам; **`acceptance/`**
  — независимый перегон лида, отдельно от `evidence/`.

## Карточки — атомарная единица делегирования

Одна карточка = один закоммиченный файл, написанный лидом ДО отправки; фиксированная инструкция
делегату: «прочитай и выполни карточку по этому пути, отчитайся строго по разделу „Return"».
Лимиты: предел символов на тело; зона записи (явные пути/один каталог); список «не трогать»;
бюджет по времени; таймаут на каждую команду внутри.

Обязательные разделы (проверяются механически): рабочий каталог, базовый коммит, зона записи,
«не трогать», шаги, гейт (одна команда + ожидаемый код), бюджет, `Return` (файлы/код
выхода/стенограммы/отклонения, ≤ 40 строк), правила остановки.

**Верификация — по диску**: лид смотрит статус дерева, сам перезапускает гейт-команду, проверяет
стенограмму с явным кодом выхода — не доверяя прозаическому отчёту делегата.

Лестница отказа: ошибка схемы → поправить и повторить раз; «выполняется»/нет результата →
прочитать диск, написать ОДНУ сузённую карточку; вторая потеря подряд → `HALT: runtime` с
доказательствами — никогда не выполнять работу карточки руками.

## Сентинелы, RESUME, диета контекста

Три фиксированные строки первым токеном сообщения или последней записью `progress.md`:

- `HALT: <причина>` — дефект, который цепочка не обходит сама;
- `AWAIT-LEAD: <что>` — контрольная точка для лида, работа вне неё продолжается;
- `CHAIN-DONE: <итог>` — делать больше нечего.

Блокирующий вопрос вместо одной из трёх строк — нарушение «ноль внешних остановок»:
`AWAIT-LEAD:` существует именно для того, чтобы вопрос не стопорил всю работу.

Каноническая строка продолжения — фиксирована дословно, никогда не переизобретается (прецедент:
импровизация с опечаткой протянулась через всю ночь):

> `RESUME: continue autonomously per chain-brief; recover state from progress.md + decisions.md;
> do not re-read code you already changed.`

**Anti-context-loss resume.** После рестарта/сжатия текущий бриф всегда старше по рангу журнала
сессии: журнал — дневник, который бриф может перекрыть. Прецедент провала: сессия подхватила
старую запись журнала и продолжила по отменённому плану вместо живого брифа.

**Диета контекста.** Большой файл — по диапазону/точечным поиском, не целиком после сжатия (файл
не менялся, менялась только память о нём); вывод команды усекается на источнике, не прогоняется
целиком; после сжатия состояние восстанавливается из брифа/decisions/progress, не перечитыванием
уже изменённого кода — нехватка этих файлов для возобновления есть дефект записи, не повод
перечитать всё дерево.

## Авто-возобновление (hook)

Плагин следит за простоем сессии и решает, повторно вставлять ли RESUME-строку. Бездействует, пока
не взведён явным флагом окружения («выключено» всегда побеждает «включено» из конфига).

**Резюмирует только корневую сессию** — прецедент: строка возобновления попала в дочерние сессии,
каждая восприняла её как волю верхнего оркестратора и стала вторым в том же каталоге. Фикс —
проверка родительства, отказывающая при неопределённости («fail closed»).

Никогда не резюмируются: явная отмена человеком; сбой авторизации провайдера; сентинел-строка;
слишком короткий интервал с прошлого резюме; счётчик «нет прогресса»; потолок резюме на сессию.
Резюмируются: голый простой без сентинела; стоп по модерации; пустой ответ модели. Два override
сильнее всего: файл-маркер «пауза» и явный env «выключить».

## Что лид отслеживает

- **Смягчение гейтов** (формы, невидимые в отчёте контура): самопропуск без сборки; частичный
  env-оверрайд ломает «всё или ничего»; красная стенограмма под зелёным именем; терминал подменён
  прямым вызовом раннера на других env-значениях; запись журнала помечена временем простоя (обход
  гейта разрывов); пак нацелен на localhost вместо стенда. Защита одна — проверка волны по
  артефакту, не по нарративу; подробнее — [10-gates-and-evidence.md](./10-gates-and-evidence.md).
- **Аудит сессии** — офлайн-разбор стенограммы: контекст к потолку, «мёртвые разрывы» (не
  нарушение при сентинеле), делегирование, запрещённые паттерны правки/git, вмешательства
  человека, модели, стопы по модерации. Неразбираемый файл — ошибка настройки; разбираемый без
  измеримых сообщений — отдельная ошибка «неизмеримо»: не выдаёт «чисто» по нечитаемым данным.
- **Бюджет вмешательств** — порог заранее (не более N, ноль запрещённых команд, молчание дольше
  M минут только вслед сентинелу), проверяется постфактум тем же аудитом.
- **Запись окружения** — версия CLI, провайдер/модель на роль, hook, оболочка — в `Entry 0` и в
  итоговом PR.

## Субагенты внешнего рига — только дайджесты

Правило Оркестратора «явная модель на каждый спавн»
([RULES.md R6](../.claude/RULES.md#r6-субагенты-только-явно-заданная-модель)) не переносится на
делегирование внутри рига: там оно регулярно сводилось к «прочитай файлы и верни дословно» —
двойная цена токенов, ноль синтеза. Правило: делегат рига возвращает **дайджест ≤150 строк с
адресами `файл:строка`**, никогда файл целиком. Старт-ритуал сессии остаётся общим —
[RULES.md R10](../.claude/RULES.md#r10-стартовый-ритуал-и-канон-модели-субагентов).

## Анти-паттерны

1. **Марафон без живой рамки** — дорого и ненадёжно, остаётся за Оркестратором, пока обратное не
   доказано в поле.
2. **Резюмирование дочерних сессий** — пропущенная проверка родительства превращает под-задачу во
   второго оркестратора в том же каталоге.
3. **Блокирующий вопрос вместо `AWAIT-LEAD:`** — легитимный вопрос не обязан стопорить цепочку.
4. **«Верни файл целиком» делегату рига** — двойная цена токенов, ноль синтеза.
5. **Доверие сводному отчёту вместо стенограммы** — «все карточки с первого раунда» при трёх
   скрытых неудачных раундах в индексе прогонов.
