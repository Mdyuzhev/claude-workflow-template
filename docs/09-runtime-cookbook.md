# 09 — Runtime Cookbook (per-stack slot)

Слот для **stack-специфичных** runtime-деталей проекта. WORKFLOW.md держит процессы в общем виде («build только через wrapper-скрипты»), а конкретику — какой скрипт, какие подводные камни, какие пути — кладёшь сюда. Разделяй по подфайлам когда раздувается (`09a-build`, `09b-e2e`, `09c-stand`, `09d-anti-patterns`, `09e-testids`).

Это **единственный** документ который намеренно содержит кальку с конкретного проекта. Всё остальное в шаблоне stack-agnostic. Здесь — твой стек.

Ниже — рубрики которые обычно нужны. Заполни под свой проект, удали неприменимое.

## Сборка (09a)

- **Wrapper-скрипты:** перечислить все (`<build>`, `<build-e2e>`, `<installer>`) и что каждый делает. Какой для какого target/платформы.
- **Чем НЕ собирать:** прямые вызовы базового toolchain которые ломают воспроизводимость.
- **Замены отсутствующих команд:** если привычной команды нет (`build:check` не существует → `<реальная проверка типов>`); per-binary vs per-lib нюансы тестов.
- **Профили сборки:** dev (быстрый, для итераций) vs release (LTO/оптимизация, для installer). Сколько занимает каждый. Когда собирать release (обычно — раз, на close эпика).
- **Версия lockstep:** точный список файлов-источников версии. Какой обновляется чем.
- **Per-target Dockerfile / окружение:** если несколько target'ов с разными требованиями (разные glibc, bundled deps) — какой Dockerfile/окружение для какого.

## E2E / тесты (09b)

- **Команды:** полный прогон (закрывает gate), targeted `--spec` (только diagnostic), isolated/triple-run.
- **Парсинг лога:** скрипт извлечения P/F/S, путь tee лога.
- **Session hygiene:** что чистить перед прогоном (весь persistent-каталог, не `*.json`), какие процессы убивать.
- **Async UI timing:** паттерн set → pause → read через два execute-блока (WORKFLOW §11.1).
- **Mock env override:** переменные окружения для подмены endpoint'ов (все или ни одной).
- **Manual visual smoke:** в каких волнах обязателен (UI-компоненты).

## Стенд / инфра (09c)

- **Test stand:** адрес, доступ (SSH через что), 24/7 сервисы и порты.
- **MCP инфра:** какие MCP-серверы, что умеют, лимиты, что запрещено без подтверждения.
- **Артефакты:** где лежат собранные installer'ы, как получить URL/путь.

## Анти-паттерны рантайма (09d)

Конкретные грабли этого стека на которые уже наступали. Каждый — симптом + причина + как не повторить. Кандидаты в REFERENCE.md если становятся правилом.

## testid / hooks / контракты (09e)

- **testid реестр:** какие есть, где определены. testid в task = testid в spec.
- **E2E hooks / exposes:** глобальные мосты для тестов (`__STORE__`, `__MANAGER__`), кто source of truth.
- **Контракты UI ↔ backend:** где сквозной flow до финального потребителя (store → pipeline → invoke → config → call-site), чтобы UI-тумблер не оказался визуальным обманом.
