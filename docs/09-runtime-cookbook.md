# 09 — Runtime Cookbook (per-stack slot)

Слот для **stack-специфичных** runtime-деталей проекта. `WORKFLOW.md` держит процессы в общем виде
(«build только через wrapper-скрипты»), а конкретику — какой скрипт, какие подводные камни, какие
пути — кладёшь сюда. Разделяй по подфайлам, когда раздувается (`09a-build`, `09b-e2e`, `09c-stand`,
`09d-anti-patterns`, `09e-testids`).

**Это единственный документ шаблона, которому намеренно разрешено нести кальку конкретного проекта.**
Всё остальное в репозитории — stack-agnostic; правило действует и на твоей копии шаблона: специфика
своего стека (имена реальных скриптов, порты, версии) живёт только здесь, а не просачивается в
`WORKFLOW.md`/`RULES.md`/`docs/05..08`.

Ниже — рубрики, которые обычно нужны. Заполни под свой проект, удали неприменимое.

## Сборка (09a)

- **Wrapper-скрипты** — перечисли все (build / build-for-e2e / installer), что каждый делает, для
  какого target/платформы.
- **Чем НЕ собирать** — прямые вызовы базового toolchain, пропускающие подготовку окружения и
  ломающие соответствие тому, что реально протестировано.
- **Профили сборки** — dev (быстрый, для итераций) vs release (оптимизация, для инсталлятора);
  когда собирать release (обычно один раз, на close эпика).
- **Изолированный идентификатор тестовой сборки** — флаг/переменная, отличающая сборку «под тесты»
  от боевой (открывает testid-хуки, гейтит exposes из `09e`); единственный источник во всех
  wrapper-скриптах, не дублируется отдельно в каждом.
- **Версия lockstep** — точный список файлов-источников версии продукта, бампающихся синхронно одним
  коммитом; расхождение подмножества источников — блокер close, не предупреждение.
- **Per-target окружение сборки** — если несколько target'ов с разными требованиями, какое окружение
  для какого.

## E2E / тесты (09b)

- **Команды** — полный прогон (закрывает гейт), точечный прогон одного сценария (диагностика),
  изолированный/тройной прогон (замер стабильности).
- **Раннер как MCP-инструмент — предпочтительный путь для агентов.** Голый вызов раннера в синхронном
  шелле блокирует сессию агента на десятки минут и теряет процесс при обрыве; detached-обвязка поверх
  MCP переживает обрыв и отдаёт машиночитаемый итог. Прямой вызов остаётся рабочим путём для человека
  без MCP-клиента.
- **Парсинг лога** — один общий парсер извлекает passed/failed/skipped из сырого вывода по
  фиксированному пути лога, не заново в каждом прогоне.
- **Session hygiene** — что чистить перед прогоном (весь каталог состояния приложения целиком, не по
  маске), какие фоновые процессы гарантированно убить перед стартом.
- **Async UI timing** — «установить состояние → пауза → прочитать» двумя раздельными шагами, не
  одним: чтение сразу после установки видит ещё не отрисованное состояние.
- **Mock-env override — контракт «всё или ничего».** Переменные, подменяющие адреса моков,
  переключаются одним коммитом целиком: часть ключей включена, часть нет — скрытая смесь боевых и
  тестовых адресов. Чек-лист «новый мок = новый ключ в одном коммите сразу во всех местах» — в наборе
  переменных, в документации ключей и в живом гейте, который проверяет их все разом.

## Стенд / инфра (09c)

- **Выданный стенд vs локальный** — общий стенд как основной путь, локальный мок-стенд как запасной,
  у каждого свой набор smoke-команд; прогон одного пути не подтверждает другой.
- **Выданный стенд не отвечает** — не тупик и не молчаливое переключение: повторить smoke → запросить
  запасной адрес у ответственного за стенд → согласовать компенсирующие доказательства и явно
  задокументировать переключение. Правку без нужды в стенде это не блокирует.
- **Инфра-MCP — лимиты использования.** Что разрешено без подтверждения (мониторинг, логи,
  health-check), что требует подтверждения (пересборка с нуля, смена боевого состояния, операция
  дороже нескольких минут).

## Анти-паттерны рантайма (09d)

Конкретные грабли этого стека. Формат каждого пункта — **симптом → причина → как не повторить**, не
голый запрет без объяснения. Кандидат в `REFERENCE.md`, если превращается в правило за пределами
одного инцидента.

## testid / hooks / контракты (09e)

- **testid — только добавлять.** Существующие не переименовываются и не удаляются внутри задачи;
  новые — свободно. Переименование — отдельное согласованное решение, не побочный эффект правки.
- **E2E-exposes — за флагом тестовой сборки.** Глобальные тестовые мосты регистрируются только под
  идентификатором из `09a`; в боевой сборке их присутствие — утечка состояния, не удобство.
- **Контракты UI ↔ backend — до конечного потребителя.** Тумблер проверяется цепочкой до места, где
  значение реально используется (состояние → backend → конфигурация вызова → эффект), не только до
  момента сохранения в сторе — иначе он существует визуально, но ни на что не влияет.
