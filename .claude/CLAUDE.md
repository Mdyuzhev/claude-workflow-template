## Начало работы

При открытии новой сессии — `/init` ([commands/init.md](./commands/init.md)), без
исключений ([RULES.md R10](./RULES.md#r10-стартовый-ритуал-и-канон-модели-субагентов)).

**Канон рабочего цикла:** бриф (техлид + владелец) → одна команда оркестратору → автономный
цикл (рекон → скоуп → фитч + self-audit → волны → close без merge → СТОП) → приёмка
владельца — единственный внешний стоп → GO = оркестратор сам выполняет FINAL —
[PIPELINE.md](./PIPELINE.md), единая точка входа в процессную модель.

**Формат отчёта — жёсткое правило, гейт, не пожелание.** Любой отчёт оркестратора владельцу
(волна, close, STOP, приёмка, FINAL) — ОДИН fenced md-блок с внешней оградой из ЧЕТЫРЁХ
обратных апострофов; вне блока максимум одна строка-подводка. Отчёт в другом виде — отчёт не
сдан. Канон-дом (требования целиком, причина, прецедент) —
[docs/10-gates-and-evidence.md §5](../docs/10-gates-and-evidence.md#5-формат-отчёта-владельцу-канон);
закрывающий гейт — [docs/08](../docs/08-housekeeping-and-pre-flight.md) + PIPELINE §8.

## Чекпоинт-протокол

Если внешний чекпоинт-канал недоступен/не определён в репозитории — чекпоинт делается через
полную перезапись файла контракта состояния (`write_file`, валиден как структура), не через
мёртвый или неопределённый канал. Правила — [PIPELINE.md §11](./PIPELINE.md).

## Роли

Четыре уровня: владелец (продуктовое направление) → техлид (бриф, post-hoc verify, не
авторит файлы) → оркестратор (единственный получатель команды цикла) → субагенты (все
правки, явная модель на каждом спавне). Полная модель, эскалация, антипаттерны —
[docs/01-roles-and-comms.md](../docs/01-roles-and-comms.md).

| `<doc-pipeline-mcp>` | `<x.y.z>` | сборка документа из контента, on-demand | `<liveness-cmd>` | `<нет / список>` |
| `<agent-driver-mcp>` | `<x.y.z>` | headless-сессия внешнего контура | `<liveness-cmd>` | `<нет / список>` |
| `<infra-mcp>` | `<x.y.z>` | наблюдение/управление хост-инфраструктурой | `<liveness-cmd>` | `<нет / список>` |

Реестр отстаёт от факта слияния — обычный класс дрейфа, закрывается тем же close-проходом,
что поднял версию сервера ([mcp/03-close-conveyor.md](../mcp/03-close-conveyor.md)). Живость
всех stdio-серверов разом — один liveness-гейт housekeeping ([docs/08](../docs/08-housekeeping-and-pre-flight.md)).
Долгоживущий процесс сервера не подхватывает правку своих исходников без рестарта клиента —
после любого version-bump сервера строка `NEEDS-RESTART: <сервер>` идёт в отчёт close/FINAL,
пока владелец не подтвердит рестарт.

## Инварианты

_см. канон: [REFERENCE.md](./REFERENCE.md) § «Инварианты»_ — канон-дом полного списка. Три
универсальных, не зависящих от стека:

- **File isolation в волне** — два субагента не трогают один файл (PIPELINE §7).
- **DoD = проходящий тест**, не «код написан» (WORKFLOW §15).
- **Build только через wrapper-скрипты проекта**, никогда базовый toolchain напрямую.

Проектно-специфичные (заполнить и держать актуальными):

- `<Иконки>` — только через единый компонент, без emoji в UI.
- `<Storage helper>` — единственный источник записи персистентного состояния.
- `<Singleton manager>` — единственный источник правды, обязателен вызов `.load()` при boot.
- Источники версии продукта: `<VERSION / package.json / config / build-manifest — перечислить>`.

## Запрещено

- Базовый toolchain напрямую вместо wrapper-скриптов сборки.
- Прямой ssh/сетевой вызов из промпта агента вместо санкционированной библиотеки.
- emoji вместо иконок UI-фреймворка.
- Инфраструктурный MCP с деструктивным флагом (пересборка с нуля, force-refresh) без
  явного подтверждения владельца.
- **Качать тулинг, не проверив наличие.** Любой драйвер/SDK/бинарь сперва проверяется на
  месте и по версии, и только при отсутствии/несовпадении качается ровно нужный билд в
  постоянное место в PATH, один экземпляр на машину. «Скачаю на всякий случай» даёт и мусор
  на диске, и плавающие красные от версии, которая просто «похожа».

## Карта CLAUDE.md в проекте

Каждый `CLAUDE.md` описывает свой уровень контекста; агент читает ближайший по иерархии к
части проекта, с которой работает. Корневой `CLAUDE.md` (репозиторий) — карта + указатель на
этот файл; этот файл (`.claude/CLAUDE.md`) — оперативный контекст всего проекта; каждый
крупный модуль/каталог кода несёт свой `CLAUDE.md` с локальными инвариантами и указателем
наверх при конфликте.
