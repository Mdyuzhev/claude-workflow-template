# MANUAL-SMOKE.md — приёмочный чек-лист владельца

Единственная ручная проверка глазами во всём цикле (PIPELINE §9.2) — она происходит один раз,
целиком, здесь, а не по кусочкам внутри волн. 5-10 пунктов, не больше: длинный список владелец
не читает, а бегло листает.

**Ставь из собранного артефакта.** Установи и запусти именно собранный инсталлятор/пакет — не
переключай рабочее дерево на ветку эпика и не запускай из исходников: это проверяет ДРУГОЕ
дерево, чем то, что реально уйдёт в релиз.

## Чек-лист

1. **Путь пользователя: создать новую сущность каждым входом UI.** Если эпик добавил новую
   сущность (новый тип сущности) — создать её через КАЖДОЕ меню/кнопку создания в интерфейсе (все
   меню и кнопки создания — в каждом месте интерфейса, где сущность можно создать), а не
   только через то место, которым воспользовался автотест. Реальный прецедент: фича была
   полностью подключена под капотом и проходила все автотесты, но физически была недостижима
   для пользователя, потому что одно из мест создания не было обновлено.
   → Ожидание: сущность создаётся из каждого входа и открывает один и тот же экран.

2. **`<Действие 1 — главный сценарий эпика>`** → Ожидание: `<конкретный наблюдаемый результат>`.

3. **`<Действие 2>`** → Ожидание: `<результат>`.

4. **`<Действие 3 — граничный случай>`** → Ожидание: `<результат>`.

5. **`<Действие 4 — что могло сломаться в соседней, не тронутой на вид зоне>`** → Ожидание:
   `<результат>`.

6. **Перезапуск приложения.** Закрыть и открыть приложение заново → Ожидание: данные эпика
   (сохранённые сущности, настройки) на месте, ничего не откатилось к состоянию до эпика.
