# CONTRIBUTING — правила участия в `<PROJECT>`

> hint: копия этого файла лежит в корне репозитория (не в `kit/`). Замени
> плейсхолдеры, удали этот блок.

Репозиторий работает по модели «main защищён»: прямой push в `main` закрыт,
любое изменение — только через Pull Request с приёмкой.

## Быстрый старт

1. Ветка от свежего `main`: `feat/<короткое-имя>`. Одна ветка — одна тема;
   периодически подтягивай main (`git merge origin/main`).
2. Коммиты — осмысленные сообщения, без цепочек промежуточных коммитов в
   финальном PR.
3. Гейты перед PR: `<typecheck-cmd>` (0 ошибок) и `<unit-cmd>` (зелёный);
   менял/добавлял end-to-end тесты — точечный прогон сценария. Полный канон —
   `_see canonical: kit/RULES.md_`.
4. Открой PR в `main` (шаблон `kit/PR-TEMPLATE.md`): что сделано, зачем, как
   проверить, прогоны текстом.
5. Дождись ревью. Merge выполняет только владелец репозитория.

## Что нельзя

Push в `main`, force-push куда-либо, удаление чужих веток, переименование/
удаление тестовых идентификаторов, правки версий и инфраструктурных зон без
согласования — полный список с обоснованиями `_see canonical: kit/RULES.md_`.

## End-to-end тесты

Стенд поднимается локально из репозитория — `kit/STAND.md`. Новые сценарии
регистрируются в общем реестре тестов проекта; генератор/насос данных в
тесте — с жёстким пределом (`_see canonical: kit/RULES.md_`). Полный smoke
локально гонять не нужно.

## Для агентов

Если задачу ведёт LLM-агент — точка входа `AGENTS.md` в корне репозитория.

## Вопросы

Канал связи — владелец репозитория.
