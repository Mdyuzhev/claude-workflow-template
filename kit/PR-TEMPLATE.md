# Шаблон описания PR

Скопировать в описание Pull Request и заполнить каждый раздел. Пустой раздел
или «сделано» без деталей — повод для ревьюера вернуть PR на доработку.
**Каждый раздел без исключений: если писать нечего — напиши «нет», не удаляй
раздел.**

```markdown
## Что сделано

Кратко, по шагам — что именно изменилось (файлы/модули, не дифф целиком).

## Зачем

Какую задачу/проблему закрывает изменение.

## Как проверить

Команда → ожидаемый результат. Одна строка на проверяемое поведение.

- `<команда>` → `<ожидаемый результат>`

### Environment record (для цепочек, исполняемых во внешнем агентском CLI)

- Версия внешнего агентского CLI, провайдер модели, модель по каждой роли
  цепочки, признак «авто-возобновление включено: да/нет», используемая
  оболочка (shell).

## Прогоны текстом

Фактический вывод команд из `kit/RULES.md` §3, не пересказ:

- `<typecheck-cmd>` → N ошибок
- `<unit-cmd>` → X passed / Y failed / Z skipped
- `<e2e-spec-cmd>` (если менялись/добавлялись end-to-end тесты) → A passed / B failed / C skipped

PR не касается кода приложения — помечай эти гейты `N/A` с причиной и
приводи здесь же проверки, которыми закрыл вклад по факту (правило и
перечень — `kit/RULES.md` §3).

Числа гейтов — полными словами честной тройкой (`N passed / M failed / K
skipped`), без однобуквенной нотации (`kit/RULES.md` §14д).

### Транскрипты гейтов

«Число гейта без закоммиченного транскрипта (UTF-8/LF) не существует» —
канон `docs/10-gates-and-evidence.md`, указатель `kit/RULES.md` §14.
Заполнить путь транскрипта для каждого применимого гейта; для неприменимого
гейта — `N/A` с причиной в той же ячейке, не пустая ячейка:

| Гейт | Транскрипт (commit:path, UTF-8/LF) |
|---|---|
| `<typecheck-cmd>` | |
| `<unit-cmd>` | |
| Изменённые/новые end-to-end сценарии | |
| Полный smoke (если гонялся на этом звене/эпике) | |

## Отбивка владельцу

Результирующая строка вызова `<notify-client-cmd> --event close ...`
(последняя строка вывода), вставленная как есть. Правило и все четыре
момента — `kit/RULES.md` §13. «Недоставлено» при недоступном канале —
валидно; пропуск самого вызова — нет: доставка без отбивки не считается
завершённой.

Для звена цепочки — отбивка `start` уже была отправлена на Entry 0
(`kit/templates/progress.md`); `close` идёт на звеньевой PR. Для одиночной
задачи — `start` и `close` отдельно.

## Self-review

Таблица «утверждение → артефакт → сверка» перед открытием PR. Минимум —
строки на каждое утверждение раздела «Что сделано» + отдельная строка на
отбивку `close`.

| Утверждение PR | Артефакт пруфа (commit:path) | Сверка |
|---------------|------------------------------|--------|
| <утверждение 1> | <commit:path> | OK / mismatch / N/A — <причина> |
| close отбивка отправлена | результирующая строка `--event close` (в разделе «Отбивка владельцу») | OK / mismatch |
| ... | ... | ... |

Гейт-числа сверяются по коммиту (`git show HEAD:<путь>`), не по рабочей
копии — платформенные различия окончаний строк маскируют реальные байты
коммита.

## Self-acceptance

Авторский pass по контракту/задаче и пруфам перед звеньевым PR или
закрытием одиночной задачи. Это НЕ внешний ролевой аудит — это авторская
сверка «заявил → доказал».

- [ ] Каждый пункт контракта/задачи — `DONE`/`PARTIAL`/`N/A` + пруф (commit:path)
- [ ] Каждый гейт — зелёный или `N/A` с причиной + вывод команды (полный текст)
- [ ] Каждое утверждение PR — сверено по таблице Self-review выше
- [ ] Отбивка `close` отправлена — результирующая строка в разделе «Отбивка владельцу»
- [ ] Последняя запись `progress.md` описывает состояние точно (не противоречит коду)

## Чистота публикации

Проверки гоняются по файлам, реально вошедшим в коммиты PR, а не по рабочей
копии. Подтвердить каждую:

- [ ] скан артефактов на персональные данные — 0 вхождений: имена пользователей
  ОС, пользовательские пути, hostname, IP-адреса, внутренние идентификаторы
  сотрудников; в фикстурах — только явно нереалистичная синтетика
- [ ] каждое утверждение этого описания о содержимом артефакта сверено с самим
  артефактом, не по памяти
- [ ] если нескрабленные версии артефактов остались в истории ветки — это
  заявлено здесь явно (решение по истории — за владельцем)
- [ ] каждый файл, на который ссылается код/README/это описание, либо есть в
  diff/репозитории, либо ссылка снята
- [ ] каждый артефакт, названный в этом описании, существует в отдаваемой
  ветке — имена совпадают побуквенно; транскрипты сняты с HEAD ветки, а не с
  промежуточного дерева (`kit/RULES.md` §14а/б)
- [ ] текстовые артефакты PR — UTF-8 без BOM + LF, проверено командой, не
  глазами (`kit/RULES.md` §14в)

## Отступления и известные ограничения

Что реализовано не так, как в исходной задаче, и почему; что осталось не
покрыто. Если отступлений нет — написать явно «нет».

## Находки глубже тикета

Диагноз, вскрывший причину глубже описанной задачи, или смежный дефект,
найденный по дороге и намеренно не тронутый. На каждую находку: что именно
сломано, где, почему не чинилось в этом PR. Если находок нет — написать явно
«нет».

## Новые зависимости

Каждая новая зависимость — с обоснованием (или «нет», если новых
зависимостей не добавлено).
```
