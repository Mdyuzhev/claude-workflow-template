# 06 — Agent-driver MCP (драйвер headless-сессий внешнего agent CLI)

Управляет запусками отдельного внешнего headless agent CLI снаружи: запуск / опрос / ожидание /
остановка, плюс read-only
интроспекция истории сессий и статистики использования — чтобы ведущий агент мог оставить
долгую внешнюю сессию без присмотра и потом узнать, что произошло, не карауля живой лог. Роли,
цепочки и приёмка внешнего контура — [docs/12](../docs/12-external-contours-and-chains.md); здесь только сам
инструмент.

## Когда использовать / не использовать

Использовать — для запуска/наблюдения headless-прогона, который должен пережить выход
управляющего процесса, и для постфактум-ответа «как выглядели сессии этого прогона». Не
использовать — как способ открыть/отредактировать credential- и конфиг-файлы внешнего CLI
(вне периметра сознательно); как ограничитель частоты запросов к внешнему API, который сам
управляемый инструмент вызывает (супервизируется только локальный OS-процесс); как
интерактивный ассистент — авто-возобновление (см. ниже) не активно, пока человек ведёт сессию
сам.

## Поверхность инструментов (семь), две половины

**Жизненный цикл.** `run` — детач-обёртка без shell в цепочке: прямой запуск исполняемого
файла массивом аргументов, либо ровно один явный фиксированный shell-хоп для типа «командный
бинарник», никогда неявная подстановка; отказывает во втором параллельном запуске на ту же
цель; честный dry-run теми же проверками безопасности, ничего не запуская. `status` — фаза,
живость, простой, посчитанный ДВУМЯ способами (рост лога / изменение рабочего дерева,
эффективный простой — меньшее из двух); переклассифицирует ложно-«работающую» запись в
«потеряна», если процесс мёртв без корректного маркера выхода. `wait` — блокирующее ожидание с
потолком до первого НОВОГО события (завершение / сигнальная строка / новый коммит / событие
вложенной под-задачи / «stall» — отсутствие роста лога И изменений дерева одновременно,
срабатывает раз за эпизод простоя); возобновляемо, как wait тестового раннера. `stop` — убивает
дерево процессов, идемпотентна на завершённом прогоне.

**Интроспекция (read-only).** `sessions` — список из хранилища CLI. `stats` — тайминг ходов,
скорость токенов, обнаружение «переполнения бюджета вывода без результата» (ход упёрся в лимит
длины, не дал ни текста, ни вызова инструмента). `models` — проходной список моделей CLI из его
конфигурации.

## Модель хранения и безопасность

Один прогон = один каталог (аргументы, статус, сырой лог с сигнальной строкой кода выхода в
конце). Интроспекция сессий НИКОГДА не открывает живое хранилище CLI напрямую — только
одноразовая временная копия, безусловно удаляемая после чтения; возвращает лишь
идентификаторы/заголовки/метки времени/счётчики, никогда текст сообщений или вызовов
инструментов (границы доверия — ../.claude/RULES.md). Каждый спавн избегает shell: массив
аргументов либо ровно один контролируемый промежуточный шаг, с заранее отклоняемым вводом,
похожим на shell-метасимволы; dry-run применяет тот же отказ, так что превью не лжёт о
реальном запуске.

## Отказы, сентинелы, эксплуатация

«Остановлено драйвером» отличается от «умер сам вне канала» (второе — «потеряна», не тихо
«работает»). Kill дерева процессов может оставить живыми собственные дочерние процессы CLI —
явно названное известное ограничение.

Длинная сессия сообщает состояние фиксированными ключевыми строками, ВСЕГДА первым токеном
строки вывода: «стоп, нужна решение человека»; «есть контрольная точка для проверки, но не
завязанная на неё работа продолжается» (легитимный открытый вопрос не должен стопорить всё
целиком); «делать больше нечего» в конце. Строка, встретившаяся внутри обычного связного
текста, не считается сентинелом — иначе случайное упоминание похожих слов ложно триггерит
остановку. Возобновление — всегда один и тот же текст, читаемый СВЕЖИМ с диска, никогда не
импровизируемый заново (импровизация однажды несла опечатку, протянувшуюся через весь прогон).

Никогда не редактировать запущенный скрипт-лаунчер: интерпретатор читает файл инкрементально,
правка на лету может рассинхронить смещение чтения и уронить процесс синтаксической ошибкой
до собственного кода завершения. Правки во время работы — через модульно загружаемый рантайм
или копирование под новым именем.

**Тесты.** Юнит- и интеграционное покрытие жизненного цикла; калибровка детектора событий
вложенной под-задачи по реальному захваченному транскрипту, а не по придуманному паттерну
(общий принцип — [01-design-rules.md](01-design-rules.md)).

## Auto-resume hook

Плагин для внешнего CLI, автоматически повторно отправляющий каноническое «продолжай» в
сессию, вставшую на паузу БЕЗ легитимного стоп-маркера — закрывает измеренный разрыв в виде
десятков ручных «подтолкни дальше» за реальные долгие сессии. Полный no-op, пока не взведён
явно; никогда не резюмирует вложенную суб-агентскую/дочернюю сессию.

**Цепочка проверок (порядок важен) на каждое событие простоя** — любая сработавшая гасит
возобновление с названной причиной: 1) маркер-файл «пауза владельцем»; 2) явный дизарм
окружением (побеждает даже «взведено» в конфиге); 3) сессия — вложенная суб-агентская/дочерняя
(никогда не резюмируется); 4) прерывание человеком; 5) сбой авторизации у провайдера модели;
6) уже присутствующий сентинел; 7) окно охлаждения с прошлого резюме; 8) guard «повторов без
прогресса» (тот же ответ повторился несколько раз); 9) предельный лимит резюме на сессию.
Только если ничего не сработало — плагин переотправляет инструкцию, читая её свежей с диска.
Резюмируются: голый простой без сентинела; остановка модерацией контента; пустой ответ модели.

**Состояние** — один маленький файл на сессию (счётчик резюме, время последнего, id последнего
сообщения, счётчик повторов без прогресса), исключённый из системы контроля версий.

**Почему несколько независимых выключателей.** Единственный компонент набора, ВПРЫСКИВАЮЩИЙ
ввод в живую сессию по событию, а не только отвечающий на явный вызов — поэтому несколько
независимых переключателей (файл-присутствие человек может снять без правки конфига; env
сильнее «включено» в конфиге) стоят перед логикой резюме, и жёсткий предел на сессию — как
последний рубеж.

**Прецедент, научивший root-only.** Первая версия резюмировала и вложенные суб-агентские
сессии — каждая читала впрыснутую инструкцию как волю верхнеуровневого оператора и сама
становилась вторым оркестратором в той же рабочей копии, вплоть до самостоятельно принятых
решений и переписанных доказательств выполнения. Фикс — проверка родительства закрыта по
умолчанию: неразрешимая проверка гасит резюме, а не пропускает («fail closed»). Второй
прецедент — повторное срабатывание много раз подряд сразу после ручной остановки человеком —
закрыт окном охлаждения плюс guard'ом «без прогресса».

**Как доказано.** Каждая ветка решения и порядок приоритета — юнит-тестами против фейкового
клиента; часть поведений проверена и живьём на реальном CLI (базовый механизм, стоп-маркеры,
граница лимита), с явной пометкой, какие поведения проверены только юнит-тестами — вместо
молчаливого заявления о полном живом покрытии. Логика решений — в отдельном простом модуле,
тестируемом изолированно от обвязки плагина.

## Аудит сессии после прогона

Отдельный проход по журналу вмешательств после долгого автономного прогона: сколько раз
человек/лид вмешался вручную, было ли молчание дольше порога без предшествующего сентинела,
использовались ли запрещённые команды. Заранее зафиксированный порог («не более N
вмешательств», «ноль запрещённых команд») превращает подозрение «сессия шла неаккуратно» в
измеримый постфактум-факт — [docs/12](../docs/12-external-contours-and-chains.md).
